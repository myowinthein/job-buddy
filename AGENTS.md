# Job Buddy

## Project Identity

Chrome MV3 extension built with WXT 0.20.26, React 19, TypeScript 5.9, Tailwind CSS v4, and Vitest 4. Single-user application: no backend or database; profile data lives in `chrome.storage.local`. Gemini is required for autofill and Resume Import; Google Drive backup is optional. Chrome Web Store is the production distribution surface; Firefox build scripts are present.

## Project Config

- ship-method: direct
- git-auto-commit: true
- git-merge-strategy: squash
- readme-style: standard

## Dev Commands

Use Node 22 (`.nvmrc`) and pnpm 11.7.0 (`package.json`).

- `pnpm install`: installs dependencies; postinstall runs `wxt prepare` to generate `.wxt/` types.
- `pnpm dev`: load `.output/chrome-mv3-dev/` unpacked in Chrome.
- `pnpm compile`: TypeScript check; `pnpm lint`: ESLint; `pnpm test:run`: Vitest once.
- `pnpm exec vitest run src/autofill/mapper.test.ts`: example focused test; `pnpm test`: watch mode.
- `pnpm build`: production build; `pnpm zip`: build plus Chrome Web Store archive.
- `pnpm build:firefox`: Firefox build; production release workflow targets Chrome.
- `pnpm format`: Prettier writes; scope formatting to the task.
- `pnpm serve:landing`: serve `docs/`.
- Integration setup is documented in `.github/SETUP.md`; env template is `.env.example`.

CI runs compile, lint, tests, and build on branch pushes/PRs. Release tags run a separate workflow with compile, lint, tests, zip, Chrome Web Store upload, and GitHub release creation.

## Architecture Pointers

- `entrypoints/content.ts` runs in all matching frames, including about:blank/origin-fallback frames. Preserve its idempotent injection guard.
- `entrypoints/popup/App.tsx` captures the source tab and immediately hands Fill Form to the background coordinator. `src/autofill/runCoordinator.ts` persists per-tab run metadata in session storage, pins frame/document IDs, serializes starts/choices, and recovers interrupted coordination through alarms. Content scripts cache each run’s scan/fill promises so recovery never rescans or duplicates AI. Closing the popup does not cancel; reopening restores active progress or pending choices. Navigation/tab closure cancels pending work. Popup status/Undo messages reinject into enumerated frames with explicit `frameId`. Results aggregate across frames sharing the latest run ID; reopening restores status. Autofill requires a saved Gemini key/model at the content-message boundary; setup does not block Undo or previous results. Explicit AI outcomes distinguish successful, unnecessary, and unavailable requests. The obsolete session-scoped AI nudge is no longer used. View details sits beside the result heading and opens Tools → Fill Details in the main options page for the captured source tab.
- `src/quick-fill/` provides the optional main-frame floating control. It uses the background coordinator with the saved fill mode, defaulting to empty fields only. Local detection sends only frame booleans; page controls derive the tab/document from the extension sender, never message-supplied tab IDs. Widget shadow DOM is excluded from the scanner. Button/fill-mode/site/position preferences stay local, persist across browser restarts, and reset with Settings. Quick Fill settings use On/Off buttons and a searchable, paginated hidden-site list.
- `src/components/popup/PopupNotice.tsx` provides the popup's shared message surface below its primary actions: blue setup/working, gray information, green completed fills, amber review/input needed, red failed actions. Setup/recovery keeps prior results and Undo available. Confirmation choices precede their buttons; Fill Form stays left and Undo/Cancel right.
- `entrypoints/background.ts` retries pending Drive sync at startup and debounces profile/mapping changes for five seconds; it also routes options-page deep links through session storage.
- `entrypoints/options/App.tsx` coordinates nine profile editor sections, Resume Import, Learned Mappings, and Settings; implementations are in `src/components/options/`.
- `src/types/profile.ts` is the canonical profile schema. `src/utils/profileValidator.ts` validates imports per section; `src/utils/migrate.ts` normalizes stored profiles.
- `src/autofill/index.ts` owns scan/fill/undo, pending matches, manual-learning watchers, and silent refill. Interrupted fills retain accepted writes in a completed ledger/result with unavailable AI and working Undo; cancellation before any accepted write reports failure. Silent refill requires the same profile ID and question identity, watches profile changes during writes, and preserves match/write confidence. `scanner.ts` creates one fresh, composed-order snapshot of native/custom controls and question groups, with per-scan label/signal caches in `labels.ts` and `signals.ts`. Question groups stay scoped to their root, form, and question container; unstructured choices can use a preceding prompt without crossing another control. Consent guards also normalize identifier separators/camel case. Application scoping excludes unrelated identified forms; `dom.ts` shares eligibility checks with the write path so detached or newly unavailable controls are rejected. `mapper.ts`, `resolver.ts`, and `filler.ts` implement matching and filling.
- `src/autofill/fieldFeedback.ts` supplies screen-reader status descriptions without visible icons, overlays, focus/hover tooltips, or extra tab stops. It preserves existing `aria-describedby` tokens in the field's tree scope and removes only Job Buddy's tokens on cleanup. Textual statuses remain in Fill Details; manual resolutions use “Confirmed by you.”
- `src/autofill/fillLog.ts` defines the metadata-only ledger and shared counting. A radio/checkbox question group counts once; kept, excluded, failed, and manual outcomes are distinct. Rule fills and AI handoffs/refinements are processing stages, so their counts can overlap. Popup final totals derive from the same ledger. `src/fill-log/client.ts` reads all frames in the latest run without scanning or filling. Live logs follow edits in content-script memory and freeze with an undone marker after Undo. `src/fill-log/retention.ts` keeps one metadata-only report across frames in session storage through a sender-validated worker message, including edits and Undo. A newer nonempty run replaces it; explicit View details can select an older open form. Selection timestamps prevent edits on unselected forms or late run completions from switching the report. Late older revisions and empty sandboxes cannot replace the selected report. Closing the source preserves this report with a neutral notice and hides Return to Form. Reset/profile replacement clears it and suppresses old open-form reports. Reports never enter profile exports or Drive backups. Fill Details is one Tools page in the main options interface, with the shared profile completion banner and without page tabs. It updates an open empty view from session changes without requiring View details. Its compact summary uses mutually exclusive final LM/rule/AI/manual sources; AI handoff counts remain a separate overlapping processing measure. Search covers field titles and readable profile paths. Native/ARIA required markers, sanitized job URLs and actual modification times are report metadata only. Core rows show outcomes/reasons; expansion provides three selectable stage nodes and a separate frame/control identity. The mapper records LM checks, trust/confirmation metadata and whether Rules ran without changing method priority. Reports preserve the original rule match score separately from write confidence, and record uncertain AI option writes separately from Gemini confidence. Node selection reads this metadata without matching or filling again; missing historical LM checks display “Not recorded.” Rule scores are numeric, LM uses trust/confirmation counts, and Gemini confidence stays qualitative. `src/fill-log/navigation.ts` stores only transient source/request metadata and uses native options-tab reuse; the options page consumes requests when visible through its unsaved-edits guard. Sidebar entry can reuse existing completed-run metadata. Legacy `fill-log.html` links redirect into this section. Return to Form focuses the captured source tab/window.
- Sibling resolution runs after individual mapping. `ruleContext.ts` scopes phones and repeated education/work/language entries to their form and structural row; calling-code siblings must share the phone's form. Current-status checkboxes require the matching section for ambiguous labels. Repeating families share `repeatingEntryResolution.ts`. `ruleValue.ts` formats identified values for native/year-only/month-year inputs and explicit salary periods/currencies; unsupported rates/scales remain manual. Sponsorship polarity comes from the applicant's question, never a negation in employer policy/helper text. Unsupported semantics stay manual in AI choice groups as well as text fields; failed eligible rule fills reach AI recovery.
- `src/resume-ai/gemini.ts` owns extraction/autofill requests; `types.ts` centralizes model priorities/defaults; `prompt.ts` and `autofillPrompt.ts` hold separate prompts. `parser.ts` also powers JSON and Drive import review. `validateResumeFile.ts` checks PDF/DOCX structure locally before upload, with bounded DOCX XML expansion. `documentAssessment.ts` reads transient Gemini document-type metadata: unrelated documents stop without model fallback; uncertain documents require confirmation before review. Assessment metadata never enters Profile or backups. `validateResume.ts` validates extracted fields; `resumeImport.ts` prepares and applies accepted changes, with list matching in `entryComparison.ts`.
- `src/utils/storageArea.ts` backs local/session wrappers. Low-level gets/removes resolve on failure by default; explicit resets reject removal failures. Local sets reject, session sets are best-effort. `getProfile()` can reject when persisting a migration.
- `src/utils/driveSync.ts` owns Drive OAuth, appdata backup, and retry state. Web Locks serialize uploads/review/disconnect across extension contexts; backup fingerprints and conditional writes protect remote changes. Both restore paths are in `SettingsSection.tsx`.
- `src/devtools/registerContentScript.ts` bootstraps WXT’s dynamic page-script registration without its websocket, using WXT’s existing script ID so hot reload updates the same registration. The dev server binds and connects through `127.0.0.1`; production uses the static manifest entry. WXT’s reload command is disabled; the config transform removes its otherwise unconditional dev listener so Chrome can start the worker with no commands declared.
- `src/devtools/` is development-only. Scenario boot replaces Chrome APIs and provider fetches before App modules load, uses in-memory storage and Drive backups, and namespaces Web Locks. Diagnostics export allowlisted metadata only. Preview integration adapters delegate to real flow code only inside these simulations.
- `docs/index.html` is a static Tailwind-CDN landing page; `docs/project-site/` is a static overview.

## Domain Rules

- Confidence thresholds live in `src/autofill/constants.ts`: fill at ≥0.60, green at ≥0.85. Yellow fills need review; red stays unfilled; a matched empty profile value is gray/noData with a 12% gray background tint, matching the opacity of other statuses. Focus styling stays untouched; the tint changes on fill and clears on Undo. Use named constants.
- Preserve two phases: scan stores `pendingMatches`; merge/overwrite consumes them without rescanning. Merge skips existing values; overwrite replaces them.
- Mapper signal order is label, ariaLabel, placeholder, name, id. Layers are learned → autocomplete → exact dictionary → fuzzy → custom-link labels → nearby context. `autocomplete="url"` deliberately has no fixed profile path.
- `mapField()` sees one field. Sibling-dependent ambiguity belongs in a post-pass: phones use a calling-code sibling; languages and expected salary start at index 0; education/work history use current/latest entry for a single occurrence and sequential indices for repeats.
- Rule-based current-status checkbox matching uses an exact-term allowlist, never fuzzy matching. AI separately considers visible non-consent checkbox/radio groups.
- Notice period has distinct virtual paths: `professional.noticePeriod.availableDate` is a calendar date; `.formatted` is a duration. Do not conflate them.
- CV aliases redirect to `documents.cv.url` for non-file inputs. Document URLs and files may coexist; preserve both, including existing cover-letter data.
- Education/work date aliases stay qualified: bare “Start Date”/“End Date” cannot safely distinguish sections. Work dates require `YYYY-MM`; education permits `YYYY` or `YYYY-MM`.
- Use `bestLabel()` for field signals and `displayLabel()` for mapping display text; display-only nearby text must not become a matching key.
- Learned mappings retain legacy strings and counted `{ path, count, label?, question?, scope?, inactive? }` entries. Question compatibility and safe path validation apply to both formats. Inactive entries round-trip through backups but never fill or transfer trust; explicit editing or a fresh manual confirmation can reactivate them. Automatic learning starts at 1, needs 2 confirmations, and resets count on conflicting paths. Explicit edits in Learned Mappings save count 2 immediately.
- Manual learning requires trusted input/change followed by blur and an exact unique match against canonical raw/display profile values in `learningValues.ts`, never the mapper guess. Email/URL punctuation is preserved; equivalent derived aliases collapse. All confidence tiers remain observable after edits. `saveElementMappings()` freezes signals and saves one deduplicated observation through the background handler with a sender-derived domain and profile revision. Extension-origin Web Locks serialize fresh reads/writes, reset/replacement, label patches, import merges, and targeted editor changes. Failed mapping reads reject writes. Nearby text is never a learned matching key. Generic repeated-field mappings follow row resolution; explicit editor choices retain entry scope.
- Profile writes atomically save any mapping changes under the learned-mapping lock. `learnedMappingProfile.ts` rebases entry-specific paths only when the original entry matches uniquely after list changes; removed/ambiguous entries become inactive instead of pointing at another entry. Generic field-scoped choices keep row resolution. Historical unsupported paths remain inactive metadata rather than being deleted. JSON/Drive Update passes the raw incoming mappings, review-base mappings and source profile into `saveProfile()`; concurrent deletions/corrections win. Conflicting paths keep the local decision; same-path snapshots use the highest count without adding confirmations. Replace explicitly adopts incoming mappings and rebases them against selected entries.
- Gemini key setup uses explicit verification and an atomic key/model/preference save. A local revision plus Web Locks prevent stale checks from restoring removed settings. Credential cleanup rejects storage errors; removal/reset leaves a local marker that suppresses development seeding.
- Gemini requests authenticate with `x-goog-api-key`, never a URL query. Autofill excludes stored document bytes, profile IDs, and unsolicited demographic details. Resume extraction sends the selected file and extracted links; profile comparison stays local. `profileData.ts` projects known profile fields at import and export/Drive boundaries.
- AI response paths are restricted to the known profile projection and per-question sensitive-data scope. Option responses use stable IDs; legacy labels/values must match exactly and unambiguously. Revalidate question identity, current selections, and the stored profile before applying answers. Explicit cancellation, Undo, navigation, and profile changes abort pending requests; closing the popup does not. Autofill requests use bounded batches, include native/section/repeating-field context, and keep timeouts active through response parsing.
- AI autofill is additive: all non-green tiers receive a pass; failures retain rules and the popup reports unavailable AI assistance; high-confidence AI may replace yellow rule values. AI self-reported confidence never writes learned mappings. Resume import has its own visible error/cancellation flow.
- Options `handleSave` computes derived fields defensively, then performs one profile write; derivation failure must not prevent the raw save. Sections never write `derived` directly.
- When changing `Profile`, audit validator, parser `FIELD_DEFS`, and relevant extraction schema. Preserve Gemini's intentional exclusions (`id`, `derived`, documents/cover letter) rather than blindly adding every field to the prompt.
- JSON export contains profile, learned mappings, and safe metadata. Drive backup contains profile, learned mappings, and lastModified. Neither includes Gemini settings or Drive token/state.
- JSON import reviews mappings alongside profile updates; `backupImport.ts` validates backup-only data and owns these merge/selection helpers. JSON/Drive callers collect `entryIndices` from `validateImportedProfile()` and pass them to `validateBackupData()` before comparison: dropped rows become inactive mappings, surviving indices move with their rows. This provenance stays transient, outside Profile/backups. These merge rules apply to Update; Replace adopts selected incoming metadata and clears omitted metadata.
- Adding a Drive payload field requires updating `syncProfileToDrive()`, `handleRestoreFromDrive`, and `handleDriveReviewSave`.
- Shared Resume/JSON/Drive import modes and conservative name/email comparison live in `importPolicy.ts`. Show Import action choices only for a possible person mismatch; empty profiles and matching identities use the normal import flow. `replaceImportedProfile.ts` starts fresh with a new profile ID, clears omitted profile data/mappings atomically, and pauses connected Drive for local replacements before the write. Appearance/Gemini settings stay local. `profileWriteLock.ts` serializes editor/import/reset writes; stale editor saves cannot cross a profile replacement.
- Resume review applies only accepted changes against fresh storage; concurrent edits to accepted fields require another review. Shared Resume/JSON/Drive review selects work and education entries, languages, and custom links individually through `entrySelection.ts`; each array is still written as a unit. Only new work/education entries use incoming-only presentation; changed entries compare current and incoming values in both Update and Replace. Resume Update imports preserve missing details in uniquely matched entries and keep saved entries omitted by the resume. Gemini responses are validated before comparison; resume requests try the selected model first, then other priority models on timeout, rate limits, or temporary unavailability. Bullet normalization preserves prose context; summary normalization merges soft wraps while preserving paragraphs. PDF hyperlink extraction uses annotations and fails to an empty list.
- Experience merges overlapping work intervals and counts inclusive calendar months. Completion uses 10 required checks across the nine editor sections; last name, salary, LinkedIn and employment history are optional. Demographic details never affect completion.

## Behavior Rules

- Read and follow the Git and safety rule files listed under Rules before working on the project.
- Work directly on main for ordinary tasks; do not create feature branches/PRs. Local commits are automatic; pushes require separate user authorization.
- Use `useToast` from `src/components/ui/useToast.ts`; `Toast.tsx` owns the provider. Section save flows use `shared/saveSection.ts`; reuse `fieldCls.ts`, dropdown hooks, and `useScrollToNewEntry.ts`.
- Shared feedback copy lives in `src/ui/feedback.ts`; rich notices reuse its text/link parts. Keep distinct recovery actions as named variants. File-size messages stay in `documentLimits.ts`, and Gemini key-check errors stay in `keyErrors.ts`. Review gallery fixtures use production message IDs, not independent message strings. Preserve the current visible gallery tabs and original IDs when refreshing captures.
- Loading feedback follows the visible action area: when a progress indicator is visible, keep the action label stable and disable it while the indicator reports progress. Without a visible indicator, put progress in the disabled action button. A section indicator behind a dialog does not count. Preserve retry/reconnect labels throughout pending actions, and do not delay fast operations to display loading.
- Vitest defaults to Node; DOM tests opt in with per-file `// @vitest-environment jsdom`. React Testing Library is installed. Keep tests under `src/`, never under WXT's `entrypoints/`.
- Autofill-matching changes require a build and live verification in a Playwright-driven Chromium against a throwaway form, in addition to relevant unit tests; verify real filled values and form validation/events.
- Preserve Tailwind v4's `@tailwindcss/postcss` setup in the extension; the static landing page has its own CDN setup.

## Hard Safety Rules

- Never read or print `.env.development` or `.env.production`; they contain real OAuth configuration.
- Never push a `v*.*.*` tag without explicit user instruction. `.github/workflows/release.yml` uploads to Chrome Web Store and creates a GitHub release; tag annotations do not select release behavior.
- Keep ESLint on v9.x while using `eslint-plugin-react@7.x`.
- Run `pnpm compile` before every commit; run the relevant existing tests before committing.
- Budget stored document bytes together with the rest of the local profile. Do not raise upload caps without reviewing storage impact.

## Known Traps

- `MonthYearPicker` emits `''` during partial input. Validate required fields at save time; preserve internal partial-entry/resync handling.
- Reset/import must reload the profile before bumping section remount/navigation state inside `handleImportComplete(afterLoad)`.
- Shared import dialogs keep review choices in their owner state. Dismissal is separate from data actions; Drive's explicit Keep Current uploads locally saved data, while Escape/backdrop/Close only dismiss and leave uploads paused. `completeDriveRestore()` validates the review before saving. A locally unchanged Drive merge still reconciles the full profile/mapping payload through `overwriteDriveWithLocal()` before reporting current, since local-only/conflicting mappings may need uploading. Retry/session-renewal alarms and connection metadata stay local and are never exported.
- Work-authorization labels come from `src/data/workAuthorization.ts`; do not duplicate the status strings.
- Section loaders retain backward compatibility for string phones/work locations, country names, older language proficiency, and currency-only salary rows. Ambiguous shared currencies remain for user selection.
- `normalizeProfile()` defaults missing/invalid salary periods to monthly and adds missing URL schemes; both load/save use it. New on-load migrations belong here.
- Field writes use `writeSession.ts` and `fieldState.ts` to snapshot original values, verify retention after framework microtasks, and roll back rejected replacements. Undo restores snapshots while preserving later manual edits; unsupported widget restoration reports incomplete. Native choices use activation, text/select events cross shadow boundaries, and actual blur/focusout updates framework touched state. Never dispatch duplicate clear events. Dropdown discovery is scoped to the trigger and newly opened portals, has a shared wait budget, and blocks submission/navigation defaults. Fuzzy option matches require compatible polarity/numbers and stay yellow. Native multi-selects accept arrays of exact values. File writes honor accept formats and verify retained files.
- Deep scanning reaches open shadow roots only; closed roots remain unsupported. Shadow labels must stay scoped to the correct root.
- Dev content/background bundles cannot rely on custom `VITE_*` variables like live popup/options code can. Gemini development seeding persists through `storage.ts`, but explicit removal/reset suppresses it.
- Dev builds use amber icons (`wxt.config.ts` and `branding.ts`); production uses blue. Theme initializes before React and follows system/light/dark through the root `.dark` class.
- Drive uses implicit-token OAuth with `drive.appdata`. Development setup requires Web Application OAuth clients with separate dev/prod redirect IDs; see `.github/SETUP.md`.
- Document uploads, Resume Import, and JSON/Drive import validation share the 4 MB file limit in `src/utils/documentLimits.ts`. Existing stored files are preserved; the per-file cap does not guarantee the whole profile fits local storage.
- Parts of `docs/project-site/` still mention a removed picker. Background backup reacts to both profile and learned-mapping saves; deletes during reset do not queue uploads.
- Restart the WXT dev server after adding an HTML entrypoint; HMR may update existing pages without emitting the new HTML. Already-open forms can retain older content scripts. On status restore, empty sandbox runs cannot supersede a nonempty form run; explicit Fill results use the requested run ID. Legacy results without detailed logs require a form refresh, never a misleading zero-field report.
- Static site brand colors are duplicated across landing and overview; update both copies together.
